## Close-control variants

Chey's question was whether every close control is "the same Liquid Glass X, and is it perfectly round on every page." It is not. Ten distinct implementations were found:

1. **`AgentToolbarIconButton` / `AgentToolbarIconLabel` — 44×44pt glass circle, X icon 17pt (default), white stroke 0.16 opacity/0.22 varies, `.glassEffect(.clear.interactive(), in: .circle)`.** Defined once (DesignTokens.swift:286-322) and used as the "Close" toolbar control on the large majority of native-toolbar sheets: settings (SettingsView.swift:262), MCP settings/review sheets (MCPBridgeSettingsView.swift:816/852/1973/2105), weekly-focus-setup (WeeklyFocusView.swift:95/951), post-proposal-review (PostProposalReviewView.swift:168), post-editor-series-detail (ResumablePostEditorView.swift:3319/4520), onboarding-pillar-editor (OnboardingView.swift:1863), ask-cy sub-sheets (AskCyView.swift:780/808/2523), plan-week's agenda-post-search (PlanView.swift:483), quick-capture (QuickCaptureView.swift:376), and consistency-goal-editor (ConsistencyGoalCard.swift:171). **~15 surfaces.**
2. **Same component, but labeled "Back" with a back-chevron icon instead of an X** — used for pushed pages that behave like the top of a mini-flow rather than a true sheet: idea-post-draft (IdeaPostDraftView.swift:186), settings pushed subpages via `SettingsPageShell` (SettingsSubpages.swift:157, ~18 pages), pillar-guide/pillar-detail (PillarsView.swift:813/1459), feed-grid (SocialGridView.swift:438), quick-capture-from-hub (QuickCaptureView.swift:378/494), resumable-post-editor (ResumablePostEditorView.swift:289), day-agenda inline editor and ScheduledPostDetailView inline editor. **~25 surfaces**, all visually identical to #1 (44×44pt) but semantically "back," not "close" — itself an inconsistency, since a couple of these (settings-add-account reached as a sheet) use the "Back" wording/icon for what is functionally a modal close.
3. **`AgentCircularGlassIconButton` — 48×48pt glass circle, icon 16pt, white stroke 0.16 opacity.** A second, larger version of the same visual idea, defined separately (DesignTokens.swift:917-942) and used only for the phone-native, edge-to-edge capture surfaces: voice-spark (VoiceSparkView.swift:397), voice-spark-link-picker (VoiceSparkView.swift:1312), voice-recording-detail (VoiceRecordingDetailPage.swift:305/313, back **and** save), creator-session (CreatorSessionView.swift:326/346 via `headerIconButton`). **5 surfaces**, 4pt larger than #1/#2 and a different opacity token for its stroke.
4. **Hand-rolled duplicate of #1/#2's geometry** in creation-hub's mobile header (CreationHubView.swift:213-241) — reimplements a 44×44pt glass circle with `AgentIconView(.close)` inline rather than using the shared component. Visually matches #1 but is a second, drifting implementation. **1 surface.**
5. **Hand-rolled, non-glass 40×40pt opaque circle** — `Color.agentSurface` fill + 1pt `Color.agentBorder` stroke, no `glassEffect` at all — used only by day-agenda-add-live-post (SocialGridView.swift:1038-1051). **1 surface**, the only close control in the app that isn't translucent glass.
6. **Plain text "Cancel" button**, toolbar `.cancellationAction` or inline, no icon at all — the largest alternate family: settings-new-destination, brand-partner-editor, brand-contact-editor, brand-activity-editor, new-pillar, post-reschedule, quick-capture-task-due-date-sheet, task-due-date-editor, post-editor-task-composer, post-editor-task-due-date, post-editor-actual-posted-date, post-editor-pillar-calendar, idea-bank-link-capture. **~13 surfaces.**
7. **Plain text "Close" button**, same placement as #6 but reading "Close" — brand-post-link-picker, brand-partner-picker (BrandCabinetView.swift:1064/1111). **2 surfaces.**
8. **"Done" only, no cancel/close at all** — task-filter (TasksView.swift:857), post-editor-media-manager (PostMediaViews.swift:897). **2 surfaces**; these have no way to discard changes, only to accept the current state.
9. **`AgentDesktopDetailBackButton` via `AgentDesktopDetailRail`** — text "Back" + chevron icon in a 36pt-tall rounded-rect hover target, Catalyst-only, replacing the hidden native toolbar: pillar-guide, pillar-detail, idea-post-draft, day-agenda, daily-focus-detail, task-detail, resumable-post-editor, ScheduledPostDetailView (desktop). **~8 surfaces**, all desktop-only variants of pages that use #1/#2 on phone.
10. **No visible control at all** — installation-invite-gate (RootView.swift:418-489) has no toolbar item; dismissal is swipe-down or the system default. **1 surface**, and the walkthrough-overlay's "Skip tour" (AppShellView.swift:583) is a plain text button with no icon, a further one-off.

So: at least 5 different geometries (44pt glass, 48pt glass, 40pt opaque, text-only, desktop back-pill) carrying the "close/back" job, two of them (44pt vs 48pt) close enough to look like a bug rather than a decision, one hand-rolled duplicate that has drifted from the shared component, and one control (day-agenda-add-live-post) that is not glass at all.

## Header variants

1. **`EditorialHeader`** (kicker + display title + optional subtitle, DesignTokens.swift:1366) — the most common pattern for full pages and top-of-sheet content: home settings root, weekly-focus-setup, post-proposal-review, brand-cabinet, idea-post-draft, pillar-guide's parent, ask-cy-conversation-history, day-agenda, daily-focus-detail/editor, account-access-gate, installation-invite-gate, feed-grid, saved-posts-library, settings-onboarding-preview (via OnboardingView). **~15+ surfaces.**
2. **`SettingsPageShell`** — a wrapper around `EditorialHeader` that also supplies the "Back" toolbar button (#2 in the close-control census) and a fixed "Settings" principal title. Used by all ~18 pushed settings subpages, giving that whole section the most internally consistent header/close pairing in the app.
3. **`AgentPageRail`** (breadcrumb text + creator avatar + settings button, CreatorAvatar.swift:114) — used only by home (HomeDashboardView.swift:800). One-off pattern not reused anywhere else, even though plan-week and idea-bank have a structurally similar need (identity + settings access).
4. **Bespoke `HStack`/`VStack` title** — not using `EditorialHeader` or any shared header component: plan-week (`MetaLabel` + display date, PlanView.swift:127), creation-hub's mobile header (CreationHubView.swift:212), day-agenda-add-live-post ("Add live post" text, SocialGridView.swift:1038). Each hand-builds its own spacing/typography.
5. **`ZStack` with centered `MetaLabel`** — activity-center ("Activity") and voice-recording-detail ("Recording"): a title centered over the content with leading/trailing buttons layered on top via `ZStack`, distinct from the leading-title layout used everywhere else.
6. **Native `.navigationTitle` only, no custom header view** — the majority of form-like sheets (post-editor-dates-sheet "Plan this post", post-editor-media-manager "Edit media", task-due-date-editor "Due date", brand-partner-editor "New/Edit partner", new-pillar "New anchor/pillar", task-filter "Filter tasks", and most of the alert/dialog-adjacent editors). These rely entirely on system chrome for the title.
7. **`AgentDesktopDetailRail`** — desktop-only replacement for the hidden native toolbar, pairing a centered title with the "Back" button (#9 in the close census) and optional trailing actions. Used everywhere #9 is used.
8. **No header at all** — cy tab (chat transcript fills the screen), account-restore (centered status only), onboarding-flow's individual pages, creator-session, voice-spark, walkthrough-overlay.

Net: two genuinely shared, reusable header components (`EditorialHeader`, and `SettingsPageShell` which wraps it), one shared identity-rail component used exactly once, and at least four more one-off or native-only patterns doing the same job.
