# Agent.cy Page Contract Ledger

This is the atomic page-by-page source of truth for the [App Behavior Map](APP_BEHAVIOR_MAP.md) and [Audit Queue](APP_AUDIT_QUEUE.md). It prevents assumptions from one page from leaking into another review.

## Scope and status

A page is an independently presented product surface: root destination, tab, navigation destination, sheet, full-screen cover, extension, widget, or Live Activity. Reusable rows, cards, fields, and buttons stay with their owning page. A nested sheet stays with its parent workflow unless it owns a different persisted record type, reusable route, or external side effect.

| Status | Meaning |
| --- | --- |
| `Mapped` | Owner and contract are recorded. Runtime behavior is not yet proven. |
| `Contract blocked` | Product sources disagree; expected behavior needs a decision first. |
| `In review` | The single page currently receiving function tracing and runtime review. |
| `Verified` | Static trace, focused tests, runtime states, and performance checks pass. |
| `Coverage gap` | The contract appears internally consistent, but named test, runtime, persistence, or performance evidence is still missing. |
| `Defect` | An approved contract is reproducibly failing with evidence. |
| `Hidden` | Code exists, but a centralized product gate prevents presentation. |

## One-page-at-a-time rule

1. Move exactly one `PAGE-*` record to `In review`.
2. Freeze its entry, outcome, exits, required states, data scope, and performance budget.
3. Trace only functions that render, derive state, navigate, mutate, persist, or call a service from that page.
4. Reproduce every required state and measure launch, interaction, scrolling, and memory behavior where applicable.
5. Mark the page `Verified`, `Coverage gap`, `Defect`, or `Contract blocked` before selecting another page.

Cross-page journeys start only after every participating page is individually closed. A journey failure belongs to the first page whose owned contract breaks.

## Checks every page receives

- Entry: fresh navigation, external entry when supported, back/dismiss, repeated entry, and stale route.
- Data: empty, one, many, missing referenced record, wrong workspace, and view reconstruction.
- System: loading, recoverable error, offline, expired access, denied permission, interruption, relaunch, and time-zone change when relevant.
- Interface: iPhone widths; Catalyst narrow/wide only if approved; keyboard, Dynamic Type, VoiceOver, Reduce Motion, and 44-point controls.
- Performance: first presentation, navigation latency, scroll/frame smoothness, query volume, repeated sort/filter/format work, body invalidation, animation cost, media decoding, synchronous file/network work, memory growth, cancellation, and cleanup.

Performance observations are recorded as `Measured regression`, `Performance risk`, or `No issue observed`. A large file or view body alone is a risk signal, not a confirmed defect.
